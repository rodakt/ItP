1. Exceptions

Errors detected during the execution of a Python program are called exceptions. You have already seen many of them:

>>> int('abc')
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
ValueError: invalid literal for int() with base 10: 'abc'

An exception is an object. Its type, here ValueError, says what kind of error occurred, and the message after the colon gives the details. If nothing handles the exception, the program stops and Python prints the traceback: the chain of calls that led to the error, from the outermost call down to the line where the exception was raised. Save the following program as report.py and run it:

def average(numbers):
    return sum(numbers) / len(numbers)


def report(numbers):
    print('Average:', average(numbers))


report([3, 4, 5])
report([])
Average: 4.0
Traceback (most recent call last):
  File "/home/student/report.py", line 10, in <module>
    report([])
  File "/home/student/report.py", line 6, in report
    print('Average:', average(numbers))
  File "/home/student/report.py", line 2, in average
    return sum(numbers) / len(numbers)
ZeroDivisionError: division by zero

Read a traceback from the bottom: the last line says what went wrong, the lines above it say where. Recent versions of Python also underline the failing part of each line with ^ characters.

C has no exceptions: a function reports an error with a special return value (such as -1 or NULL) or with errno, and the caller can silently ignore it. C++ and Java have exceptions similar to Python’s, with try/catch instead of try/except. Unlike Java, Python has no checked exceptions: a function does not declare which exceptions it may raise, and the caller is never forced to handle them.

Many exceptions are built into Python. They form an inheritance hierarchy, with BaseException at the top. Nearly all of them derive from Exception, among others:

  • ValueError – a function receives an argument of the correct type, but with an inappropriate value,
  • TypeError – an operation or function is applied to an object of an inappropriate type,
  • NameError – a local or global name is not found,
  • IndexError – a sequence index is out of range,
  • KeyError – a dictionary key is not found,
  • ZeroDivisionError – division or modulo by zero,
  • FileNotFoundError – a file or directory is requested but does not exist; together with PermissionError, IsADirectoryError and others, it is a subclass of OSError, the base class of errors reported by the operating system,
  • RecursionError – the maximum recursion depth is exceeded (Lab 5).

The whole hierarchy is shown in the documentation. The few exceptions that do not derive from Exception are not errors: for example, KeyboardInterrupt is raised when the user stops the program with Ctrl+C (in Thonny, the Stop button).

2. Handling exceptions

Exceptions are handled with the try statement. Its basic form is:

try:
    # code that may raise an exception
except SomeException:
    # code that handles the exception

It works as follows:

  1. The block after try is executed.
  2. If no exception occurs, the except block is skipped, and the try statement is finished.
  3. If an exception occurs, the rest of the try block is skipped. If the type of the exception matches the type named after except (it is that class or its subclass), the except block is executed, and the program continues after the try statement. Otherwise, the exception passes to the function that called the current one, and so on up the call stack. If no handler is found, the program stops with a traceback.
>>> try:
...     x = int('abc')
...     print('This line is not executed')
... except ValueError:
...     print('Not a number')
...
Not a number

A try statement may have several except clauses, for different exceptions. The first one that matches is executed, so a clause for a subclass, such as FileNotFoundError, must come before a clause for its base class, OSError. A clause can also handle several exceptions given as a tuple. With as, the exception object is assigned to a variable; str(e) is its message:

>>> try:
...     d = {'a': 1}
...     print(d['b'])
... except (KeyError, IndexError) as e:
...     print('Missing:', e)
... except Exception as e:
...     print('Something else went wrong:', type(e).__name__, e)
...
Missing: 'b'
WarningDo not catch everything

An except clause without an exception type, or except Exception, catches all errors, including the ones you did not expect: a typo in a variable name (NameError) or a wrong argument (TypeError) in the try block would be reported as, say, invalid user input. Catch only the exceptions you know how to handle, and keep the try block short. A bare except: catches even KeyboardInterrupt, so the program cannot be stopped with Ctrl+C.

NoteAsk forgiveness, not permission

In C you would check that a string consists of digits before converting it. In Python it is common to simply try the operation and handle the exception if it fails. This style is called EAFP (easier to ask forgiveness than permission), in contrast to LBYL (look before you leap). The checks are often harder to get right than they seem: '-3'.isdigit() is False, although int('-3') works, and '²'.isdigit() is True, although int('²') fails.

3. The else and finally clauses

After the except clauses, a try statement may have an else and a finally clause:

try:
    # code that may raise an exception
except SomeException:
    # code that handles the exception
else:
    # code executed if no exception was raised in the try block
finally:
    # code that is always executed

At least one except or finally clause must be present.

  • The else block is executed if the try block raised no exception. Code that should run only after a success belongs here rather than at the end of the try block: an exception raised by it is not caught by mistake by the except clauses meant for the try block.
  • The finally block is executed always, as the last part of the try statement: after the try block finished normally, after an exception was handled, and also when an exception was not handled, or when the try statement is left by return, break or continue. It is used to release resources, such as files or network connections, whatever happens.

The finally clause is not known in C++ (where destructors release resources); Java has it, with the same meaning.

4. How the with statement works

In Lab 4 you opened files with the with statement, which closes the file even if an error occurs. Without with, the same effect is achieved with finally:

f = open('example.txt', encoding='utf-8')
try:
    text = f.read()
    # further processing of the file
finally:
    f.close()

Note that open() is called before the try statement: if it fails, there is no file to close, and the variable f does not even exist.

The with statement packs this pattern into a single line:

with open('example.txt', encoding='utf-8') as f:
    text = f.read()
    # further processing of the file

The expression after with must return a context manager, an object with two special methods: __enter__(), called at the beginning of the block (its result is assigned to the variable after as; for a file, it is the file itself), and __exit__(), called when the block ends, in any way, also by an exception. The __exit__() method of a file closes it.

with releases the resource, but it does not handle the exception: an error raised by open() or by the code in the block still has to be caught by a try statement around the with statement.

5. Raising exceptions

An exception is raised with the raise statement, followed by an exception object, usually created with a message:

>>> raise ValueError('invalid value')
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
ValueError: invalid value

In Lab 5, the function triangle_area() returned None for sides that do not form a triangle. Such a result is easy to overlook, and the error shows up later, far from its cause:

>>> 2 * triangle_area(1, 1, 5)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
TypeError: unsupported operand type(s) for *: 'int' and 'NoneType'

A function that cannot compute its result usually raises an exception instead. It stops the computation at once, the message explains the cause, and the caller may handle the error if it knows how to:

def triangle_area(a, b, c):
    if not is_triangle(a, b, c):
        raise ValueError(f'no triangle with sides {a}, {b}, {c}')
    ...

The built-in functions behave the same way: int('abc') raises ValueError rather than returning a special value.

Inside an except clause, raise without an argument raises the handled exception again. This is useful when you want to react to the error, e.g. print a message, but leave handling it to the caller:

try:
    ...
except ValueError:
    print('Invalid data, giving up')
    raise

A doctest may check that a function raises an exception. The expected output starts with the first line of the traceback and ends with the exception type and message; the lines in between are replaced with ..., since doctest ignores them:

def triangle_area(a, b, c):
    """Return the area of the triangle with sides a, b and c.

    >>> triangle_area(3, 4, 5)
    6.0
    >>> triangle_area(1, 1, 5)
    Traceback (most recent call last):
        ...
    ValueError: no triangle with sides 1, 1, 5
    """

6. The assert statement

The assert statement checks a condition that should always be true if the program is correct:

assert condition, message

If the condition is false, the AssertionError exception is raised with the given message (the message is optional). Otherwise nothing happens:

>>> x = -1
>>> assert x >= 0, 'x must be non-negative'
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
AssertionError: x must be non-negative

As the assert macro in C, which is removed by NDEBUG, Python’s assertions can be switched off: when Python is run with the -O option, assert statements are not executed. (In Java they are off by default.) So use assert to state facts about your own code and in tests, but never to check user input or the arguments of a function; raise an exception for those.

Warningassert is not a function

assert (x >= 0, 'x must be non-negative') never fails: the condition is a non-empty tuple, which is always true. Python warns about it with SyntaxWarning: assertion is always true, perhaps remove parentheses?.

7. Unit tests

A unit test checks a small part of a program, typically a single function, by calling it with known arguments and comparing the result with the expected one. The doctests of Lab 5 are unit tests, written in the docstrings. Larger test suites are kept in separate files.

Modules

Every .py file is a module: another program in the same directory can import it by its name, without the extension, and use its functions. For example, if the file geometry.py defines triangle_area(), then a program in the same directory can use

from geometry import triangle_area

When a module is imported for the first time, all its code is executed, so it should only define functions. Code that you use to try the functions out goes under if __name__ == '__main__':, where it runs only when the file is run as a program (Lab 5).

Tests with assert and try

A test function calls the tested function and checks the result with assert. A test that expects an exception uses a try statement: it fails if no exception, or a different one, is raised. The test program runs all its test functions; if any of them fails, the program stops with an AssertionError, and the traceback shows which test failed.

The unittest module

Writing tests is a common practice in software development, and there are libraries that make it easier. The standard library provides the unittest module (similar to JUnit in Java); pytest is a popular external library. With unittest:

  • the tests are methods of a class derived from unittest.TestCase; their names start with test_ and they take the parameter self (classes are the topic of Lab 9; for now, follow the template),
  • the checks are made with methods such as self.assertEqual(a, b), self.assertAlmostEqual(a, b) (for floats) and self.assertTrue(x), which print both values when they fail,
  • with self.assertRaises(ValueError): checks that the block raises the exception, replacing the try statements of the previous exercise,
  • unittest.main() finds and runs all the tests, and prints a report. Unlike the program of the previous exercise, it does not stop at the first failed test.
