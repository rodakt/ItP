1. Functions as arguments

In Lab 7 you passed functions to the higher-order functions of the standard library, such as sorted(), max() and map(). Writing your own is just as easy: a parameter may be bound to a function, and the function is called with round brackets like any other. Consider the sums

\[ \sum_{k=1}^{n} k, \qquad \sum_{k=1}^{n} k^2, \qquad \sum_{k=1}^{n} \frac{8}{(4k-3)(4k-1)}. \]

The three loops that compute them would differ only in the expression added at each step. That expression can be made a parameter, a function term of one argument:

def summation(n, term):
    total = 0
    for k in range(1, n + 1):
        total += term(k)
    return total
>>> def identity(k):
...     return k
...
>>> summation(100, identity)
5050
>>> summation(100, lambda k: k * k)
338350

The function summation() expresses the general idea of a sum, and term its particular terms, just as sorted() expresses sorting and key the particular order. Mathematically, summation is a function that takes a function as an argument, like the operator \(\sum\) itself, or the derivative and the definite integral.

2. Functions returning functions

A def statement may appear inside the body of another function. It creates a new function object each time the outer function runs, and that object can be returned:

>>> def make_power(exponent):
...     def power(x):
...         return x ** exponent
...     return power
...
>>> square = make_power(2)
>>> cube = make_power(3)
>>> square(5), cube(2)
(25, 8)
>>> square
<function make_power.<locals>.power at 0x7f3a1c2b5d80>

The inner function power uses the variable exponent of the enclosing function. The call make_power(2) has long finished when square(5) is called, but square still remembers exponent = 2, and cube its own exponent = 3. A function together with the variables of the enclosing functions that it uses is called a closure. The body of make_power could equally be return lambda x: x ** exponent.

A name used in a function is looked up in this order: the local variables, the variables of the enclosing functions, the global variables and the built-in names (the LEGB rule: Local, Enclosing, Global, Built-in).

NoteClosures in C, C++ and Java

Standard C has no nested functions; a function can keep values between calls only in static or global variables, shared by all its callers. C++ lambdas list the variables they capture, by value ([=]) or by reference ([&]); a lambda that captures a local variable by reference and outlives the function leaves a dangling reference. Java lambdas may capture only local variables that are effectively final. In Python a closure keeps the variables it uses alive as long as it exists itself.

WarningA closure remembers variables, not values

The inner function sees the current value of the variable when it is called, not the value at the moment it was created:

>>> powers = [lambda x: x ** k for k in range(4)]
>>> [p(2) for p in powers]
[8, 8, 8, 8]

All four functions use the same variable k, whose value is 3 after the comprehension has finished. Creating the functions with make_power(k) gives each of them its own variable; so does the idiom lambda x, k=k: x ** k, since a default value is computed when the function is created (Lab 5).

3. The nonlocal statement

A closure can not only read the variables of the enclosing function, but also keep a state between its calls. An assignment makes a name local in the whole body of a function (Lab 5), so to assign to a variable of the enclosing function, declare it with nonlocal, just as global declares a global variable:

>>> def make_counter():
...     count = 0
...     def counter():
...         nonlocal count
...         count += 1
...         return count
...     return counter
...
>>> c = make_counter()
>>> c(), c(), c()
(1, 2, 3)
>>> d = make_counter()
>>> d(), c()
(1, 4)

Each call of make_counter() creates a new variable count, so the counters c and d are independent. Without nonlocal, count += 1 raises UnboundLocalError. Unlike the global counter of Exercise 5.7, the state is hidden: no other code can change count.

nonlocal is needed only to assign to the name. Modifying a mutable object that the name refers to, e.g. values.append(x) for a list values of the enclosing function, is not an assignment and needs no declaration.

4. Variable number of arguments

print() and max() accept any number of positional arguments. A parameter written with a star, by convention *args, collects all the remaining positional arguments into a tuple; a parameter written with two stars, by convention **kwargs, collects all the remaining keyword arguments into a dictionary:

>>> def show(*args, **kwargs):
...     print(args, kwargs)
...
>>> show()
() {}
>>> show(1, 'a', [2], color='red', size=3)
(1, 'a', [2]) {'color': 'red', 'size': 3}
>>> def total(*numbers):
...     result = 0
...     for x in numbers:
...         result += x
...     return result
...
>>> total(1, 2, 3), total()
(6, 0)

The parameters come in the order: ordinary parameters, *args, keyword-only parameters, **kwargs. A parameter after *args can be passed only by name; that is why you write print(a, b, sep=''), whose signature is print(*objects, sep=' ', end='\n', file=None, flush=False).

The stars also work in the opposite direction, in a call: f(*seq) passes the elements of seq as separate positional arguments, and f(**d) passes the items of the dictionary d as keyword arguments:

>>> numbers = [3, 1, 4]
>>> print(*numbers, sep=', ')
3, 1, 4
>>> options = {'sep': '-', 'end': '!\n'}
>>> print(*numbers, **options)
3-1-4!

A function def wrapper(*args, **kwargs): return f(*args, **kwargs) therefore passes any arguments on to f unchanged, which you will need in the next section.

In C, a function with a variable number of arguments, such as printf(), reads them with the macros of <stdarg.h> and must learn their number and types from other arguments, e.g. from the format string. In Java, a parameter int... numbers collects the arguments into an array, like *numbers in Python; Java has no counterpart of **kwargs.

5. Decorators

A function that takes a function and returns a new function, usually an extended version of its argument, is called a decorator. The following decorator prints each call of a function before making it:

def trace(f):
    def wrapper(*args, **kwargs):
        arguments = ', '.join(map(repr, args))
        print(f'{f.__name__}({arguments})')
        return f(*args, **kwargs)
    return wrapper


def factorial(n):
    return 1 if n == 0 else n * factorial(n - 1)

factorial = trace(factorial)
>>> factorial(3)
factorial(3)
factorial(2)
factorial(1)
factorial(0)
6

The traced function replaces the original one under the same name, so the recursive calls inside factorial go through wrapper as well. This is so common that Python has a special syntax for it: writing @trace in the line before def factorial(n): has the same effect as the assignment factorial = trace(factorial) after the definition.

@trace
def factorial(n):
    return 1 if n == 0 else n * factorial(n - 1)

The function returned by a decorator is a different function: its name, factorial.__name__, is 'wrapper', and its docstring is that of wrapper, i.e. none. The doctests of a decorated function are then silently lost, since doctest does not see them. The decorator functools.wraps copies the name, the docstring and other attributes of f to wrapper, and every decorator should use it:

import functools

def trace(f):
    @functools.wraps(f)
    def wrapper(*args, **kwargs):
        arguments = ', '.join(map(repr, args))
        print(f'{f.__name__}({arguments})')
        return f(*args, **kwargs)
    return wrapper
